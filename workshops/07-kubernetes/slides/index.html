Kubernetes on a Laptop

Who restarts it at three in the morning?

What a cluster is

kubectl is an HTTP client. The cluster is the API server plus whoever listens to it.

Desired versus actual

Interactive · desired vs actual

A Deployment says how many pods should exist. A controller loop compares that with what does exist and fixes the difference, forever. Change the number. Kill a pod. Watch.

    You never say do this. You say this should be true, and a loop keeps making it true.

    The Pod is the unit

    one or more containers  ·  one IP  ·  one name

    Not restarted. Replaced.

    Kubernetes never runs a container. It runs a Pod.

    Deployment → ReplicaSet → Pods

    apiVersion: apps/v1
kind: Deployment
metadata:
  name: redis
spec:
  replicas: 1     # how many
  selector:       # mine = this label
    matchLabels:
      app: redis
  template:       # a pod, written down
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7
    Deploymentone per app · owns the templates
    ↓
    ReplicaSetone per template · keeps N pods
    ↓
    Podsredis-7c9d-x2kq4 …

    Labels are the glue. Every “which pods?” is answered with a label.

    A Service is a stable name for moving pods

    In compose it was redis. Here it is redis. Same word, and the Service is why.

    Rolling update and rollback

    api:1 ×3ReplicaSet A
    →
    2 old + 2 new≤25% up, ≤25% down
    →
    api:2 ×3ReplicaSet B · A kept at 0

    kubectl rollout undo deployment/api

    Undo is instant: nothing is rebuilt, ReplicaSet A is scaled up again.

    kind, and the :latest trap

    kind load docker-image api:1
    the node has its own image store copy the laptop's image in
    image: api:1
    IfNotPresent use what is there
    image: api
    = api:latest → Always → ImagePullBackOff

    No tag = :latest = “ask the registry”. Tag everything.

    What the laptop cluster is not

    • One node. Nowhere else to reschedule to.
    • No load balancer. port-forward stands in.
    • No disks. Redis forgets when its pod dies.

    A cloud cluster adds exactly these three, and charges for them. The YAML does not change.
