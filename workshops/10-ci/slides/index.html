A CI Pipeline That Builds Your Image

The same no, for the whole team.

A workflow is a file GitHub runs

  • push starts a run of every workflow whose on: matches
  • a run is jobs, in parallel unless one needs another
  • a job is steps, on one fresh VM
  • a step is uses: an action, or run: a command
name: ci
on: push
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-go@v7
      - run: go test ./...
      - run: go run …/govulncheck@v1.8.0 ./...
  build:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: docker/login-action@v4
      - uses: docker/metadata-action@v6
      - uses: docker/build-push-action@v7

In the repository, next to the code: reviewed, versioned, diffed.

Every job is a fresh machine

Nothing carries over. That is why checkout appears twice.

Who is GITHUB_TOKEN?

  build:
    needs: test
    permissions:
      contents: read
      packages: write
    runs-on: ubuntu-latest
    steps:
      - uses: docker/login-action@v4
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
