The year
Software engineering workshop series · the year · 10 slots

One narrow thing per afternoon

Every workshop is the same shape: a 15-minute talk for the mental model, then 90 minutes where everyone types the same code at a pace the slowest keyboard in the room can follow. That pace is the binding constraint. Working assumption used throughout: at follow-along tempo, with explanation and checkpoints, a room manages roughly one new line of code per minute and a short command in less, so a lab gets a budget of about 50 hand-typed lines of code, plus commands; everything above that (test data, boilerplate, config the students have already seen) is pasted from the page, and the page says which is which.

Languages. Two for the year, chosen per topic: TypeScript on Deno where the platform APIs do the work (WebCrypto, Deno.serve, the built-in test runner) and Go where its standard library and ecosystem are the natural home (TLS, Argon2, Prometheus). Both install as one binary on every OS. Workshop 1's Go server is built inside a container, so nobody installs Go until workshop 3; workshop 6 reuses its Dockerfile. Kubernetes and Git are language-neutral.

1 · Containers from the ground up

Image vs container, the run / ps / logs / exec / stop / rm lifecycle, ports, environment and volumes. Then a Dockerfile for a small Go web server built without Go on the laptop, the layer cache, and a multi-stage build that shrinks the image from close to a gigabyte to about thirteen megabytes. Typed: 27 lines of Dockerfile and 40 commands; the Go program is pasted.

3 · Storing passwords properly

Plaintext → SHA-256 → per-user salt → PBKDF2 at OWASP’s 600,000 rounds: students write the dictionary attack, crack 9 of 10 hashes in under a second, then price the same attack out of reach and add a constant-time compare and self-upgrading hashes. Go, standard library only. Typed: 64 lines, code and commands; everything else is pasted.

Why this order

The year splits into a security block (2–4), a breather (5) and an infrastructure block (6–8). The security workshops need nothing but a language runtime, so they come first, before any fragile tooling is asked of the room. The infrastructure block is consecutive because 7 and 8 both build on 6 and the compose file needs to still be in students' fingers. Git sits between the blocks because it needs no installation, has no code to type, and gives the room a week of low load before the heaviest afternoon.

The language sequence falls out naturally: Go (inside Docker, read only), Deno, Go, Go, none, both, none, Go, Deno, YAML and Go. Students meet Deno first (closest to JavaScript they already know), get two consecutive Go afternoons to become comfortable with it, and see both side by side in workshop 6, where the point is that services need not share a language. Nobody has to context-switch languages two weeks running until they have seen each one twice.

Within the security block, passwords before TOTP would tell the cleaner story ("something you know, then something you have") and would introduce constant-time comparison a week before TOTP reuses it. TOTP is listed first only because it is written and ready; if workshop 2 has not been announced yet, swap 2 and 3 and nothing else on this page changes, except that Go then comes first.

Workshops 9 and 10 come after the core year on purpose. 9 returns to security with everything from 2–4 in hand: WebCrypto and Deno from 2, constant-time compare from 3, and the idea of what to trust from 4. 10 closes the year by automating what 1, 5 and 6 did by hand: build the image, the pre-commit "no", the compose integration test.

The load curve, using the typed-line budgets above: light, light, medium, none, heavy, medium, medium, then 9 and 10 medium (60 each). Only one afternoon is heavy and it is the one with the most slack around it.

If slots are short

Drop 10 first (it can shrink back to the 10-minute CI demo at the end of 6), then 9, then 8. 8 goes last of the three because it is the only one of the core year nothing else depends on, and 6 and 7 already complete the "from one container to a cluster" story. Do not drop 5 to make room: a year of consecutive build-something afternoons has no recovery week.
