Software engineering workshop series · 10 workshops

One narrow topic per workshop

TechBytes is a series of hands-on workshops on topics every working developer meets sooner or later: containers, passwords, HTTPS, Git, observability, OAuth, CI. Each one has the same shape: a 15-minute talk for the mental model, then a 90-minute lab where everyone types the same code together.

Each lab has a small typed-line budget, roughly 40–65 hand-typed lines (code plus commands), so the whole room can keep pace. Everything else is copied from the page, which marks what to type and what to paste. Every workshop comes with:

  • a workshop page with prep pack, lab, solution and instructor notes;
  • a slide deck with speaker view;
  • a printable manuscript;
  • runnable code in code/.

What you need. A laptop, a terminal and a text editor, plus the tools below. Workshop 1 builds its Go server inside a container, so it needs no Go. Each workshop page lists its full prep.

  • Docker (Desktop or Engine): workshops 1, 6, 7, 8 and 10.
  • Go: 1.24 or newer for workshop 3 (the prep installs 1.27); Go 1.27 for workshops 4, 6, 8 and 10.
  • Deno: Deno 2 for workshops 2, 6 and 9, and Deno 2.9 for workshop 8.
  • kind and kubectl: workshop 7.
  • openssl, curl and Firefox: workshop 4. Workshops 6 and 9 also use curl.
  • Git 2.23 or newer: workshop 5. Workshop 10 also needs git.
  • A GitHub account: workshop 10 needs a personal account with a public repository. Workshop 9 uses one for its real-login step; the rest of that lab runs against a local fake GitHub.

1 · Containers from the ground up

Image vs container, the run / ps / logs / exec / stop / rm lifecycle, ports, environment and volumes. Then you write a Dockerfile for a small Go web server without installing Go, use the layer cache, and finish with a multi-stage build that shrinks the image from close to a gigabyte to about thirteen megabytes. You type 27 lines of Dockerfile and 40 commands; the Go program is copied from the page.

2 · TOTP from scratch

RFC 6238 in TypeScript on the built-in WebCrypto API, checked against the RFC test vectors with deno test, then against your own phone. You type 45 lines in seven functions and one class; the Base32 encoder, the test file and two small scripts are copied from the page. No Docker, no dependencies.

3 · Storing passwords properly

Plaintext, SHA-256, per-user salt, then PBKDF2 at OWASP’s 600,000 rounds. You write the dictionary attack, crack 9 of 10 hashes in under a second, then make the same attack too expensive and add a constant-time compare and self-upgrading hashes. Go, standard library only. You type 64 lines, code and commands; the rest is copied from the page.

4 · HTTPS: be your own certificate authority

Two openssl commands make a CA, two more and a six-line extension file make a certificate for localhost. A ten-line Go server serves it over TLS, and Firefox and curl refuse it until the CA is trusted. A Go client with its own root pool and openssl s_client show trust as code, and you produce the three ways a padlock fails on purpose. You type 55 lines, code and commands; the rest is copied from the page.

5 · Git for the things that go wrong

Break a prepared repository six ways and repair it each time: bisect names the commit that broke the test, interactive rebase squashes four WIP commits, the reflog undoes a hard reset and a deleted branch, a conflict is resolved by hand, and a pre-commit hook says no. No code to write. You type 38 commands; the rest is copied from the page.

6 · Two services and a queue with Docker Compose

An API in Go that enqueues jobs, a worker in Deno that consumes them from a Redis list, and one compose.yaml that starts all three on a private network. Then scale the worker to three and kill one mid-job to see what a plain queue loses. You type 56 lines, code and commands; the rest is copied from the page.

7 · Kubernetes on a laptop

Deploy workshop 6’s three containers to a kind cluster on your laptop: one typed Deployment plus a generated Service, scale to three, kill a pod and watch it return, roll out api:2 and roll it back. You type 53 lines, code and commands; the rest is copied from the page.

8 · Logs and metrics you can actually use

Structured JSON logs with log/slog, a hand-written Prometheus /metrics page (a counter and a histogram in thirty lines), and Prometheus and Grafana in Compose. Three PromQL expressions and a two-panel dashboard find the deliberately slow endpoint, and a request id joins the graph to the log line that says why. You type 55 lines, code and commands; the rest is copied from the page.

9 · Log in with GitHub (OAuth 2)

The redirect dance by hand with Deno.serve: an authorize URL with state, a callback that checks it, the code traded for a token server-to-server, then /user, because GitHub issues no OpenID Connect ID token for user login, so identity is an API call. A local fake GitHub, copied from the page, runs the lab offline and lets the tests run themselves. The same code then logs in with your real account, PKCE binds the code to the app that asked for it, and a test proves each of the three checks (state, exact redirect, PKCE). You type 60 lines, code and commands; the fake GitHub, the HTML helpers and the tests are copied from the page.

Open the workshop →SlidesManuscriptDenobuilds on 2–4security

10 · A CI pipeline that builds your image

GitHub Actions on workshop 1’s Go server: a test job on every push, a build job that pushes the image to ghcr.io with the workflow’s own short-lived token (no personal access token anywhere), and govulncheck failing a branch that pins golang.org/x/text v0.3.7 and calls the vulnerable function. A ruleset turns the red check into a blocked merge, and the fixed image runs on your laptop. You type 60 lines, code and commands; the rest is copied from the page.
